Model Registry

The governance layer on top of your runs

A central, named model

Every registered version keeps its full lineage back to the exact run, code and data that produced it.

Descriptions, comments and tags document why a version exists.

Versions move with aliases

Older workflows used fixed stages: None → Staging → Production → Archived.

Current MLflow uses flexible aliases instead — e.g. @champion, @challenger — that serving code always points at.
